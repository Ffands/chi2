# Лог разработки и идей

## Историческая сводка (восстановлено из контекста):
- **OCR и парсинг**: Начата работа над продвинутым распознаванием текста. Была идея использования `ocrCustomSuffixes` для корректного чтения чисел с буквами (1.5K, 2M, 3B и т.д.).
- **UI и баги**: Починили отображение шестеренки (она теперь не скрывается), исправили баг с пережатием OCR (даунскейл больше не ломает чтение текста, переведен на ползунок).
- **Roadmap**: Планировалось разделить кликер на Одиночный, Многоцелевой и Инженерный режимы.

## Реализовано ранее (Идеи 4 новых режимов):
1. **Блоки команд (Макросы-циклы)**: При выполнении условия проигрывается заранее записанный блок команд (череда кликов).
2. **Хотбар пресетов**: Вынос на панель UI быстрых кнопок для ручного переключения между разными скриптами/макросами на лету.
3. **Мультипоточность (Параллельное исполнение)**: Независимая работа нескольких пресетов/команд одновременно (например, один поток следит за HP, другой фармит).
4. **Умный обработчик (Экономика/Аналитика)**: Сравнение двух чисел с экрана (с учетом суффиксов) через OCR. Пример: Баланс >= Цена -> Покупка. Или Баланс < Мин.ставка -> Стоп.

## Сохраненный лог чата (Полная история фичей)
В логе зафиксированы обсуждения и реализация следующих фичей:
1. **Поддержка JSON-профилей**: Загрузка сценариев напрямую из файлового менеджера.
2. **Продвинутое сравнение цветов**: Вторая метка-компаньон в виде ромба для сравнения двух пикселей (c пунктирной линией).
3. **Препроцессинг OCR (Малоконтрастный текст)**: Фильтр ColorMatrix (3.0), обесцвечивание, апскейл.
4. **Тестер препроцессинга**: Отображение в imgPreview результата фильтрации OCR.
5. **K-Means бинаризация**: Улучшение чтения текста на сложных фонах, обработка ошибок `try/catch`.
6. **Оптимизация простоев**: Разделение задержек. Rate-limit (150мс для цвета, 300мс для OCR).
7. **Кэширование изображений (`cachedTargetBitmap`)**: Избавление от декодирования Base64 в каждом цикле.
8. **Downscaling (Качество)**: Снижение разрешения поиска через `checkStep` (оптимизация матрицы IntArray).
9. **Горячие клавиши (Громкость ВНИЗ)**: Быстрое скрытие/показ HUD панели.
10. **4 Новых Режима**:
    *   **Subroutines (Блоки команд / Макросы)**: Возможность запустить другой профиль при выполнении условия.
    *   **Hotbar**: Горизонтальная панель (⚡) для быстрого переключения профилей.
    *   **Мультипоточность (Параллельное исполнение)**: Пулы `ExecutionThread`, независимые метки работают параллельно. Очередь жестов `gestureQueue` для предотвращения зума. Опциональный "Синхронный мультитач".
    *   **Smart OCR (Умный обработчик)**: Парсинг суффиксов (k, m, b), математическое сравнение (>, <, ==).
Все функции успешно вшиты в ядро `AutoClickService`, модели `Models.kt` и UI `UIManager.kt`.

## Обновление лога (Текущая сессия)

### Чекпоинт 1: Архитектура, Оптимизация и Устранение Багов
*   **Оптимизация и причесывание кода:** Исправление синтаксических ошибок в Kotlin-коде после масштабных слияний.
*   **Восстановление стабильности:** Проведена полная проверка скобок и компиляции. Ядро `AutoClickService` и интерфейс `UIManager` приведены к рабочему состоянию.

### Чекпоинт 2: Визуал и Свайпы
*   **Дизайн суб-меток:** Заменили ромб на стильные полупрозрачные прицелы с перекрестием. Голубой цвет для конца свайпа (S+ID), пурпурный для сравнения цвета (C+ID).
*   **Режимы свайпа (Настройки):** Добавлен выпадающий список: Вектор (по суб-метке), К метке (по ID с динамической линией), Ломаная линия (для записанных жестов).
*   **Отрисовка:** Динамическая отрисовка линий между метками (`canvas.drawPath` и стрелки). Отрисовка траектории записанных многоточечных жестов.

### Чекпоинт 3: Метка "Менеджер" (Сложная логика)
*   **Новый тип метки:** `NodeType.MANAGER` (в UI отрисовывается фиолетовым цветом).
*   **Интерфейс:** Полностью кастомный блок настроек, скрывающий ненужные вкладки (Тайминги, Свайпы, Анти-Детект). Позволяет добавлять N-строк "Триггер № X ➔ Метка № Y", плюс "Fallback" (переход, если ничего не совпало).
*   **Ядро:** Написан асинхронный итератор `evaluateManagerRoutes`, который последовательно проверяет Триггеры и делегирует переходы, не выполняя кликов самостоятельно. Логика IF/ELSE полностью реализована в приложении, соответствуя "Инженерному программируемому режиму" из Roadmap.


### Чекпоинт 4: Исправление компиляции (Финализация)
*   **Сборка:** Полностью устранены все синтаксические ошибки и неразрешенные ссылки (Unresolved references). 
*   Исправлены конфликты Android-импортов (`Spinner`, `Intent.putExtra`), восстановлены методы планировщика `scheduleNextExecution`, а также пропатчены перечисления режимов (`AppMode.SEQUENTIAL`). 
*   **Итог:** `gradle assembleRelease` теперь должно проходить без ошибок сборки.

### Чекпоинт 5: Режим Записи и HUD
*   **Скрытие HUD:** Красный крестик [✖] на панели теперь только скрывает её (`View.GONE`), а не убивает службу `AutoClickService`. Панель можно вернуть нажатием кнопки "МЕНЮ АВТОКЛИКЕРА" в приложении.
*   **Реалтайм Запись (Снижение задержки):** Жесты в режиме записи теперь транслируются на экран почти мгновенно (50мс для кликов, 100мс для свайпов) сразу после отпускания пальца. При этом в саму метку сохраняется **реальное** время удержания пальца для корректной работы макроса. Это решает проблему медленного проигрывания записанных действий в момент записи.
*   **Точность меток:** Центрирование меток исправлено (теперь вычитается половина ширины/высоты маркера, метка ставится строго по центру тапа).

### Чекпоинт 6: Возврат записи, фикс скрытия HUD
*   **Режим записи:** Откатил изменения задержки записи, вернув её к предыдущему состоянию (до попыток сделать реал-тайм 50/100мс), так как это работало хуже.
*   **Сворачивание HUD / Скрытие значков:** Исправлена проблема, из-за которой HUD не менял свой размер (оставалось пустое пространство). Контейнеру кнопок `topScroll` выставлен `WRAP_CONTENT`, а при нажатии на кнопку сворачивания (`[-]`) теперь принудительно вызывается `windowManager.updateViewLayout`.
*   **Закрытие HUD [✖]:** При закрытии панели крестиком теперь происходит полная очистка (как если бы процесс был убит): останавливается воспроизведение и запись, удаляются все метки и визуальные элементы с экрана. При этом служба не выключается (`disableSelf()` убран), что позволяет не терять выданное разрешение. Возобновить работу можно из главного приложения через "МЕНЮ АВТОКЛИКЕРА".

### Чекпоинт 7: Поиск и исправление слабых мест (Weak spots)
*   **Скролл в больших меню (NO_LIMITS bug):** Убран флаг `FLAG_LAYOUT_NO_LIMITS` у главного меню `modMenu`. Ранее при раскрытии клавиатуры или длинном списке настроек (например, в редактировании метки) окно могло уходить за пределы экрана, делая невозможным скролл до кнопок «Сохранить». Теперь Android корректно ограничивает максимальную высоту меню размерами экрана, и `ScrollView` работает штатно.
*   **Тулбар хотбара (⚡):** Добавлен принудительный вызов `windowManager.updateViewLayout` при скрытии панели макросов. До этого оставалась прозрачная некликабельная зона после закрытия хотбара.
*   **Потеря данных при перетаскивании (Drag & Drop Loss):** Добавлен вызов `service.autoSave()` в событиях `ACTION_UP` (окончание перетаскивания) для всех маркеров: 
    - Основные метки кликов/свайпов
    - Метки конца свайпа
    - Метки зоны распознавания текста (обе)
    - Метки сравнения цвета
    *Ранее новые координаты маркеров сохранялись в памяти, но не записывались на диск до следующего изменения настроек. Если пользователь перемещал метку и закрывал приложение, её позиция сбрасывалась. Теперь координаты надежно сохраняются в ту же секунду.*
