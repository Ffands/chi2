# План развития автокликера (Roadmap)

## 1. Управление и UX (Главное приложение)
* **Запуск из приложения:** Избавляемся от "костыля" с постоянным включением/выключением службы специальных возможностей (Accessibility Service) в настройках Android. Если служба уже включена, запуск и остановка плавающего виджета должны происходить по кнопке из самого приложения (MainActivity) через систему Intent-ов или биндинг службы.
* **Централизованный выбор режима:** Пользователь выбирает режим работы (Одиночный, Многоцелевой, Инженерный) в основном приложении перед запуском UI.
* **Сохранение и Загрузка:** Возможность сохранить выстроенную логику меток как "профиль" (скрипт) прямо в приложении. Не нужно каждый раз настраивать заново. Возможность делиться профилями с другими игроками.
* **Дерево сценария:** Всю выстроенную логику, зависимости и последовательность маркеров можно будет наглядно посмотреть в виде структуры в самом приложении.

## 2. Плавающий UI (UX панель) и новый прицел
* **Новый прицел:** UI кликера больше не должен перекрывать пиксель. Переработаем его в виде тонкого перекрестия с прозрачным центром, чтобы было чётко видно целевой пиксель.
* **Мод-меню дизайн:** Плавающее меню должно быть похоже на игровые читы (mod menu) — перекрывать экран, позволять быстро всё настроить, и сворачиваться. Настройки меток сгруппированы по категориям (например: "Проверка цвета", "Логика и переходы"). Никакого хаоса на экране.
* **Состав главной плавающей панели:**
  * Кнопка «Старт / Стоп».
  * Кнопка «Добавить метку/триггер».
  * Кнопка «Скрыть / Показать все метки» (чтобы настроенная сетка не мешала обзору экрана, но оставалась активной в фоне).

## 3. Режимы работы

### 3.1. Одиночный режим
* Классический кликер в одну точку с поддержкой условия по цвету. Использует прозрачный прицел.

### 3.2. Многоцелевой режим
* **Мультитач:** Поддержка полностью одновременных кликов сразу по нескольким областям.
* **Индивидуальные настройки меток:** Время удержания, задержка перед переходом к следующей цели, число повторений.
* **Жесты:** Запись и воспроизведение сложных жестов (свайпов). Запись минимум двух одновременных жестов.

### 3.4. Инженерный программируемый режим
Инженерный кликер превращается в полноценную визуальную среду программирования:
* **"Метка" (Активный триггер):** Элемент, который ВЫПОЛНЯЕТ нажатие (клик).
* **"Триггер" (Пассивный триггер):** Элемент, который ТОЛЬКО ПРОВЕРЯЕТ цвет или условие (нажатия не делает).

**Функционал элементов:**
* **Мульти-клик (Объединение):** Выбор, с какими другими метками эта метка будет срабатывать *абсолютно одновременно*.
* **Подсвет (Базовое условие):** Клик происходит только если цвет под перекрестием совпадает с заданным.
* **Цикл проверок (Ожидание события):** Сценарий останавливается и ждёт ("не переходить, пока не выполнится"), периодически проверяя цвет под меткой. Задается лимит количества таких проверок до перехода.
* **Ветвление логики (If / Else):**
  * Полноценные логические операторы: И (AND), ИЛИ (OR), НЕ (NOT). (Например: если Метка 1 красная И Триггер 2 синий -> сделать то-то).
  * Маршрутизация сценария. Задается переход при успехе (ДА) и неудаче (НЕТ).
  * *Пример:* Триггер №5 проверяет цвет. Если цвет красный (ДА) -> управление передаётся Метке №6 (и она делает клик). Если цвет не подошёл (НЕТ) -> переход на Метку №7.
  * После клика самой себя (например, Метка 1 нажала на красное) можно задать переход на следующую цель.
* **Индивидуальный «Скрыватель»:** Возможность скрыть UI конкретной метки (чтобы не мозолила глаза), с последующей возможностью отобразить её обратно через главную панель.
* **Кастомизация UI:** Изменение цвета самого маркера и присвоение ему номера (1, 2, 3...) для визуального удобства.
